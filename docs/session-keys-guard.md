- The source change adds pending-block signer selection and wrong-domain pool cleanup; the additional CREATE2 and pool-domain tests are outside the production manifest.

The CREATE2 hypothesis does not yield a Session Keys registration bypass. `CREATE` and `CREATE2` share `evm.create`; that path rejects the exact registry address and every address with a permanent `Used` tombstone before contract initialization (`core/vm/evm.go:498-508`, `588-591`). A constructor may inherit the owner's `tx.origin`, but registry mutation still requires depth zero, immediate caller equal to origin, no caller code, and zero value (`core/vm/evm.go:250-265`). The signed-block control deploys its factory with an owner-key transaction at nonce 0, registers the existing session with a separate owner-key transaction at nonce 1, then calls the factory using a session-key transaction at the session's nonce 0. The constructor sees owner `tx.origin` and factory `msg.sender`; its valid new-key proof cannot substitute for an owner-signed registry transaction. The direct registration increments the owner's nonce to 2, while the session call increments only the session nonce to 1. The constructor's nested registry attempt fails; direct owner registration and the following authorized session call succeed. The separate collision test derives the real CREATE2 destination but seeds nonce or registry state directly for its negative controls; those controls do not claim an on-chain path to manufacture session state. I found no feasible short-address preimage claim for `0x1237`; the runtime guard compares the full 160-bit address.

The target whitelist is address-and-selector based, not code-hash based. `Validate` checks the configured address and first four calldata bytes, and EVM dispatch loads the code currently installed at that address (`builtin/sessionkeys/registry.go:287-301`, `core/vm/evm.go:274-285`). A signed-block test demonstrates the consequence under the repository's legacy SELFDESTRUCT behavior: the authorized CREATE2 target self-destructs and is redeployed at the same address with different runtime code; the session remains active and the replacement observes `msg.sender` as the session and `tx.origin` as the owner. The test sets `ShanghaiBlock` to nil to exercise that behavior. This is an address-based authorization trust boundary: owners must trust the target's upgrade, deployment, and self-destruct controls for the session lifetime. It is not a registry bypass, and no generic selector blacklist is justified by this model.

Address roles are intentionally asymmetric. Owners and keys cannot be zero, the registry `0x1237`, GAplo `0x1234`, APLO and block-oracle builtins `0x1235`/`0x1236`, or active precompile addresses `0x1`–`0x9`; keys must also be unused and non-existent, and owners must have no code (`builtin/sessionkeys/registry.go:320-338`). A target may be any nonzero address except the registry, including a builtin or precompile, if the owner explicitly whitelists it. Such a target uses the normal dispatch for that address. Contract creation separately rejects builtin, registry, and Used-key destinations (`core/vm/evm.go:498-508`).

Direct registration remains an ordinary signed EOA transaction to the registry, so it uses and increments the owner's normal nonce. The registry also requires the new key's low-S proof of possession; the proof binds owner, key, effective chain ID, target, ordered selectors, allowances, and expiry. Chain ID is the replay domain, not a unique genesis identifier: transactions and proofs can be replayed across networks that intentionally share a chain ID. Unprotected session and direct registry transactions are rejected in block processing, independently of TxPool admission (`core/state_processor.go:100-110`). No attack is inferred from direct `SetCode` or `SetNonce` state APIs; the repository has no EIP-7702 transaction path in this audit scope.

Accounting checks remain consistent across consensus execution. The session reserves owner native value plus the amount in an exact APLO `transfer(address,uint256)` call (`builtin/sessionkeys/registry.go:527-534`); the APLO builtin debits the owner and charges that remaining allowance only when the immediate caller is the active session (`builtin/aplo/aplo.go:160-188`). The maximum GAplo fee is checked against the separate remaining fee allowance before gas purchase, while GAplo balance reservation uses the fee cap and refunds return unused gas at the effective price (`core/state_transition.go:252-296`, `515-559`). Reverts restore top-level value and builtin allowance writes while retaining the nonce and actual gas fee. The top-level value-payer override is limited to depth zero and the immediate session sender (`core/vm/evm.go:204-207`), so nested internal calls cannot charge native value to the owner through that override. Incoming native credits, including internal CALL and SELFDESTRUCT, resolve the permanent key tombstone to its owner (`core/state/statedb.go:381-388`). The session remains the top-level caller and nonce lane; nested calls preserve ordinary caller semantics, so an allowed target that authorizes by `tx.origin` alone may expose owner authority to that permitted call. This is an application policy risk inherent in the requested model.

The prior TxPool initialized one `LatestSigner(chainconfig)` and used it across fork heights; when an EthPoW fork was scheduled, that helper selected `ChainID_ALT` even for pre-fork pending blocks. That could reject valid primary-domain transactions before the fork and admit alternate-domain transactions that block processing rejects. The frozen code derives the signer for `head + 1`, drops transactions invalid in the new domain while the old signer can still identify their lanes, updates fork flags and local-account signer state, and then reinjects against the new signer (`core/tx_pool.go:1359-1385`). This is a pool admission/liveness issue, not a consensus signature bypass. The lightweight LES pool is outside this full-node audit.

### Earlier security and consensus findings

The session key remains the transaction signer and nonce lane. On the authorized top-level call, `msg.sender` is the session key and `tx.origin` is its owner; nested calls preserve ordinary EVM caller behavior. Registration and revocation require a direct, zero-value owner EOA call. An owner appearing only as `tx.origin` cannot authorize a nested registry mutation. The single top-level target and exact four-byte selector are checked before execution; a whitelisted contract can still make its normal nested calls, so target contracts must not rely on `tx.origin` alone for authorization.

Registration requires a low-S key-possession signature binding the owner, key, effective chain ID, target, ordered selectors, budgets, and expiry. Invalid or absent signing domains are rejected rather than treated as chain ID zero. This closes the fresh-address squatting issue: an owner cannot register somebody else's unproven key. Proofs use the chain ID replay domain, not a unique genesis identity; networks intentionally sharing a chain ID can replay the proof, just as they can replay EIP-155 transactions.

Session transactions reserve the maximum GAplo fee against the owner's separate remaining fee allowance and charge the actual fee. Top-level native value and APLO builtin transfers debit owner funds and the APLO allowance. EVM reverts restore value and allowance changes while retaining the signer nonce and actual gas charge; invalid transaction prechecks do not commit state. Pool reservations account for pending owner/key spending and are rechecked when the head changes. Expiry is inclusive through the last block, cleanup follows transaction and reward execution, and bounded owner/expiry indexes, finite lifetime, and permanent used-key tombstones prevent unbounded cleanup and address reuse. Revoke and expiry remove authorization but keep the native credit recipient mapped to the owner.

Genesis derivation, commit, and setup use the same allocation normalization: registry `0x1237` is code-free with nonce one and empty genesis storage, and GAplo `0x1234` has exactly the canonical runtime. Conflicting registry allocations and noncanonical GAplo runtime are rejected. Runtime state checks fail closed; they do not initialize protocol accounts during the first transaction. Recovery verifies the persisted allocation against the original header state root before writing. Native credits, including internal CALL, SELFDESTRUCT, fee/DAO credit, and consensus rewards, use the tombstone recipient. Canonical GAplo `transfer`, `transferFrom`, and root-only `refund` recipient routing preserves malformed ABI words so the contract decoder rejects them. Arbitrary token storage is outside this routing guarantee.

The source and tests cover expiry/revoke cleanup, snapshots, branch isolation, processor/miner state-root parity, transaction-pool reservations, and import/reorg/restart. Regular EOA identity is explicitly exercised, and a fresh `--dev` smoke sends its first ordinary transaction successfully. The GAplo mining reward tier intentionally reads the owner's stake, while `stake` and `unstake` still use the actual caller and do not spend owner stake. I found no focused test asserting a session-triggered `mine` payout against owner stake, so that specific reward interaction remains unverified.
