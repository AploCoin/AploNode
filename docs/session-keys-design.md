# Session Keys ADR

Authority: the user’s explicit target semantics and `session_keys_design.pdf` (3 pages), informed by `Protocol-Native Session Keys.pdf` (17 pages). The latter has contradictory caller semantics; the former governs. Session Keys are permanently native from a new Aplo genesis; no activation height or compatibility fallback is provided.

Registration rejects zero/self, previously used, funded/nonce-used/contract/builtin/precompile addresses and owners that are or were sessions. Delegation chains and renewal are forbidden. Tombstones remain forever (paid registration state); inactive keys cannot originate transactions at all heights. The whitelist constrains only the top target+selector, so an allowed contract can take arbitrary indirect actions, including delegatecall; applications must not authorize owner-only operations merely through tx.origin. APLO native value budget covers top transaction value, not an application contract's own balance. Gas-token budget covers fees, not all ERC20-like transfers. APLO.transfer through the native builtin also charges its explicit amount against APLO allowance, in addition to top-level value; session staking remains keyed to the session caller and does not gain access to owner funds or stake.

GAplo integration must match the chain canonical deployed bytecode; do not silently support arbitrary replacement bytecode. Canonical credit paths are transfer, transferFrom and root-only refund; mine stores mining metadata and protocol rewards are credited separately to the payer. No token storage migration is planned; recipient ABI canonicalization preserves existing storage layout. New genesis normalization rejects registry code/storage and a nonce above one, supplies nonce one even for a registry account with native dust, and requires canonical GAplo code for explicitly preallocated token storage. There is no marker or first-transaction initialization. Normalization is shared by root derivation and persistence and leaves caller-owned allocations intact. Genesis recovery rejects an old spec and verifies the original header root before flushing a native spec. Existing databases without native protocol genesis accounts are incompatible and must be replaced by a freshly initialized disposable devnet, without deleting retained data or keys. Historical Ethereum genesis configurations that delay EIP155 are not valid native Aplo genesis configurations; their unrelated fork schedules have not been rewritten.

## Metering and ordering

Create costs 400,000 + 25,000 per selector, including at most 32 selectors. Each selector pays a fresh storage slot (~20k) and future clear (~5k). Fixed creation cost covers metadata/index slots and their later clear/swap operations. Revoke costs 300,000 with no automatic refund; getSession costs 100,000 including its bounded selector reads. Up to 32 expirations occur per height (about 1,500 bounded storage writes at worst), prepaid by creation and independent of block tx gas. Absolute expiry slots avoid modulo wrap aliasing; only [current,current+1000] is admissible; block>MaxUint64-1000 cannot create.

Validation checks gasLimit*feeCap against both owner GAplo funds and remaining gas budget. Purchase debits gasLimit*effectivePrice, refund returns unused gas at effectivePrice, and allowance charge is usedGas*effectivePrice. A successful top value and APLO builtin transfer decrease APLO allowance; EVM revert/OOG rollback all native moves/explicit transfer charges while nonce and actual fee remain. Invalid messages rollback chain state and GasPool. Access-list preparation occurs before the transaction snapshot and before fee execution. Mining rewards and incoming credits never modify allowances. Zero-beneficiary tips are burned because canonical GAplo prohibits mint-to-zero.

Txpool checks candidates for the next block, maintains signer nonce lanes, filters both budgets and revalidates delegation after head changes. Executable pending lanes conservatively reserve cumulative value/APLO transfers and fee caps across sessions and ordinary transactions sharing the payer. Unfundable queued suffixes remain queued; head changes revalidate reservations. Sequential block execution checks current owner balances again, preventing aggregate overspending independently of local pool policy.
