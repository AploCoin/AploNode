Registration rejects zero/self, previously used, funded/nonce-used/contract/builtin/precompile addresses and owners that are or were sessions. Delegation chains and renewal are forbidden. Tombstones remain forever (paid registration state); inactive keys cannot originate transactions after activation. The whitelist constrains only the top target+selector, so an allowed contract can take arbitrary indirect actions, including delegatecall; applications must not authorize owner-only operations merely through tx.origin. APLO native value budget covers top transaction value, not an application contract's own balance. Gas-token budget covers fees, not all ERC20-like transfers. APLO.transfer through the native builtin also charges its explicit amount against APLO allowance, in addition to top-level value; session staking remains keyed to the session caller and does not gain access to owner funds or stake.

GAplo integration must match the chain canonical deployed bytecode; do not silently support arbitrary replacement bytecode. Canonical credit paths are transfer, transferFrom and root-only refund; mine stores mining metadata and protocol rewards are credited separately to the payer. No token storage migration is planned; recipient ABI canonicalization preserves existing storage layout. Historical activation checks no code/storage at 0x1237 in parent state and canonical GAplo bytecode, then initializes registry nonempty account and journaled marker so EIP161 cannot delete storage. Operators must verify these prerequisites; choose height through governance separately.

## Metering and ordering

Create costs 400,000 + 25,000 per selector, including at most 32 selectors. Each selector pays a fresh storage slot (~20k) and future clear (~5k). Fixed creation cost covers metadata/index slots and their later clear/swap operations. Revoke costs 300,000 with no automatic refund; getSession costs 100,000 including its bounded selector reads. Up to 32 expirations occur per height (about 1,500 bounded storage writes at worst), prepaid by creation and independent of block tx gas. Absolute expiry slots avoid modulo wrap aliasing; only [current,current+1000] is admissible; block>MaxUint64-1000 cannot create.

Validation checks gasLimit*feeCap against both owner GAplo funds and remaining gas budget. Purchase debits gasLimit*effectivePrice, refund returns unused gas at effectivePrice, and allowance charge is usedGas*effectivePrice. A successful top value and APLO builtin transfer decrease APLO allowance; EVM revert/OOG rollback all native moves/explicit transfer charges while nonce and actual fee remain. Invalid messages rollback chain state and GasPool. Access-list preparation occurs before the transaction snapshot and before fee execution. Mining rewards and incoming credits never modify allowances. Zero-beneficiary tips are burned because canonical GAplo prohibits mint-to-zero.

Txpool checks candidates for the next block, maintains signer nonce lanes, filters both budgets and revalidates delegation after head changes. Executable pending lanes conservatively reserve cumulative value/APLO transfers and fee caps across sessions and ordinary transactions sharing the payer. Unfundable queued suffixes remain queued; head changes revalidate reservations. Sequential block execution checks current owner balances again, preventing aggregate overspending independently of local pool policy.

Native dust at 0x1237 cannot prevent activation: existing APLO balance and EOA nonce are preserved. Only an actually empty registry needs nonce=1 to survive EIP161; funded nonce-zero EOAs retain nonce zero. Existing code/storage collisions require a different governed migration and are rejected.
